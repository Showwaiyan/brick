----- CLAUDE -----
This is my suggestion, not a decision — nothing gets recorded unless you say so.

I'd check rate-limiting **before** the hash comparison. Reasoning: if an account is already locked out or throttled, you want to reject the attempt immediately without spending time on a bcrypt/argon2 comparison (that's deliberately slow). Checking the limit first also means a locked-out attacker can't use timing differences to learn whether their guess was close. Common pattern: look up attempt count → if over threshold, reject with a rate-limit response → otherwise compare hash → on failure, increment the attempt counter.

Want to go with that, something else, or pull in the "what happens on failure" gap (g4) at the same time since they're related?
