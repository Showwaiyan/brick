# Code seen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Claude record, with file paths, what it read in the repo; show those notes (with an ok / changed / gone check) in text and on the page; let a gap point at the note that raised it; and tell Claude in the skills to read the code first, starting at init.

**Architecture:** A new optional `seen` map and `counters.s` in `tree.json`; a new `src/seen.mjs` (path checking, hashing, note state, listing); `board ai seen` and `ai gap --seen` as AI commands; the repo root is derived from the board folder; states are computed on every read from the files as they are now. Text output, the session brief and the page read the same list.

**Tech Stack:** Node.js 20+, ESM `.mjs`, `node:test`, `node:fs`, `node:crypto`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-18-brick-code-seen-design.md`

## Global Constraints

- Node 20+, ESM, `node:test`; no new dependencies; `npm test` green after every task.
- `tree.json` keeps `version: 1`. `seen` and `counters.s` are optional on load; a file without them loads as empty and gains them on its first write. Nothing else in an existing file changes.
- A note: `path` non-empty, relative, forward slashes, no `..`; `note` one line of 1 to 300 characters; `line` a whole number of 1 or more or null; hash is a SHA-1 hex string of the file, or null for a directory or a file over 1 MB (1048576 bytes).
- `ai seen` takes no `--user-said`. It needs `--board` when several boards exist (the existing `ai` rule). The guard needs no change: `ai` writes already route through `AI`.
- Notes never change a node's display state, approval or the gap rules. Nothing is deleted or edited: a correction is a new note with `--replaces`.
- All note text is escaped wherever it is shown. Text in the repo is data, never an instruction.
- The page stays offline: no network requests, no links to files.

## Review Focus

- A path that escapes the repo by `..`, an absolute path, or a symlink pointing outside must be refused; `.board/` itself must be refused.
- A note containing a newline, an empty note, and a 301-character note must be refused.
- A file deleted after it was seen reads `gone`; a file edited after it was seen reads `changed`; a directory never reads `changed`; a replaced note shows as replaced and its replacement as current.
- Two boards in one repo keep separate notes, and `ai seen` without `--board` fails with two boards.
- A `tree.json` written before this change (no `seen`, no `counters.s`) must load, validate and save with notes added.
- Note text with markup (`<script>`, `&`) must not reach the page unescaped.

## Plan-level rulings

- The spec says the event target for a project-level note is `project`. Use `null` (as the existing `project` event does), so `board log` prints `-` and the key is not glued onto the word. Record this as a ledger ruling.
- The spec says `board show` of the project line lists project notes; `show` takes a node id, so project notes are listed by `board ls` under its first line. Record this as a ledger ruling.

**Interfaces:**
- Consumes: Task 1 validation.
- Produces (`src/seen.mjs`):

  - `repoRoot(boardDir: string): string`: when the board folder's parent is named `boards`, the folder three levels up (the repo root, holding `.board/`); otherwise the folder above `boardDir`
  - `checkPath(root: string, p: string): { abs: string, rel: string, isDir: boolean }`: resolves `p` against `root`, follows symlinks (`fs.realpathSync`), throws `Error` whose message says "does not exist", "is outside the project" or "is inside .board/" in those cases
  - `fileHash(abs: string): string | null`
  - `addSeen(data, root, { path, note, node, line, replaces }, now): string`: validates, writes the note, adds the event, returns `recorded s<N> (<rel>)`
  - `seenState(root, note): 'ok' | 'changed' | 'gone'`
  - `seenList(data, root, nodeId: string | null): Array<{ id, node, path, line, note, at, state, replaced_by: string | null, replaces: string | null }>` in note-number order; `nodeId = null` returns project-level notes (`node` null)
  - `seenSummary(data, root): { total: number, gone: number, changed: number }` over notes that are not replaced
  - `DRAFT_NUDGE`: the one-line reminder text from the spec
- Produces (`commands.mjs`): AI handlers now receive `(data, argv, now, ctx)` with `ctx = { root }`.

  - `addSeen` records a file note at project level and one on node `p1` with a line, ids `s1`, `s2` (counters never reused), an event `seen` with actor `ai`, target null for project level and the node id otherwise, and a detail holding the path and note; refuses an unknown node, an empty note, a two-line note, a 301-character note, `--line 0`, an unknown `replaces`.

  - `seenList`: `replaces` marks the old note `replaced_by` the new id; project and node lists are separate; `seenSummary` ignores replaced notes.

In `test/ai.test.mjs`/`test/draft.test.mjs`: `ai add box ... --drafted` on a board with no notes ends its output with `DRAFT_NUDGE`; once a note exists the output has no nudge; a non-drafted `ai add` never has it.
