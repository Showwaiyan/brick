# UI labels (short title, tagged node boxes) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show a short title for the board (root node, heading, overview card) and draw each node box as a bold title plus a row of styled tags (id, state, source, counts).

**Architecture:** A pure `title.mjs` gives the shown title. A pure `tags.mjs` decides which tags a node has and lays them out; `flow.mjs` reserves blank rows in the pele label, renders with pele, then injects the tags as SVG into each node group by string post-processing (no DOM in Node), falling back to the old plain second line if that fails. Tag styles are CSS classes shared by the diagram and the node page.

**Tech Stack:** Node.js 20+, ESM `.mjs`, `node:test`, pele 1.6.0 (already a dependency). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-18-brick-ui-labels-design.md`

## Global Constraints

- Node 20+, ESM, `node:test`; no new dependencies; `npm test` must stay green after every task (currently 193 tests).
- The page stays offline: no network requests, no new script sources. All text from the board is escaped (labels through `escapeLabel`, HTML through `textContent`/`escapeHtml`).
- `project.title`: one line, 1 to 40 characters, optional. `project.name` is never rewritten.
- `ai project --title` alone needs no `--user-said`; `--input` and `--output` still do.
- Tags carry words, not colour alone: `Drafting`, `Approved`, `Has gaps`, `Superseded`, `AI draft`, `N sub`, `N gap(s)`.
- Tag order: id, state, source (`AI draft`), sub-steps, gaps. The `AI draft` tag keeps today's rule: source `ai-draft` and state not `approved`/`superseded`.
- Nothing changes in node, gap or id rules, approval, or `tree.json` apart from the optional `project.title`.

## Review Focus

- A title with markup characters (`<b>`, `&`, `"`) or a long single word must not break the label or the page.
- A node with all five tags must wrap to a second row and the box must grow to hold it; no tag may cross the box edge.
- A node inside the "Dropped" subgraph (superseded) and a node with a dotted id (`p1.1`, drawn as `p1_1`) must still get tags and must still resolve on click.
- A board with no `project.key` (older file) must still draw ids without a prefix and a root without a key tag.
- If pele's output cannot be post-processed, the page must still show every node's id and state.
- An existing board with no `title` shows a trimmed name, never an empty heading.

### Task 2: Tags in the diagrams

**Files:**
- Create: `src/tags.mjs`, `test/tags.test.mjs`
- Modify: `src/flow.mjs`, `test/flow.test.mjs`, `test/draft.test.mjs`
- Test: `test/tags.test.mjs`, `test/flow.test.mjs`

**Interfaces:**
- Consumes: Task 1 `pageData(...).project.shown`; page data nodes (`state`, `source`, `active_children`, `open_gaps`, `title`); `fullId`.
- Produces (`src/tags.mjs`):
  - `export const TAG = { H: 20, PAD: 8, GAP: 6, CHAR: 7.2, MIN_WRAP: 150, MAX_WRAP: 260 }`
  - `tagsFor(pd, id): Array<{ kind: 'id'|'state'|'source'|'sub'|'gap', text: string }>`
  - `rootTags(pd): Array<{ kind: 'key', text: string }>` (empty when no key)
  - `tagWidth(text: string): number` = `Math.ceil(text.length * TAG.CHAR) + 2 * TAG.PAD`
  - `layoutTags(tags, wrapWidth): { rows: Array<Array<{ kind, text, x, w }>>, width: number }` greedy left to right, `x` from 0, `TAG.GAP` between tags, a new row when the next tag would pass `wrapWidth`; `width` is the widest row
  - `wrapWidthFor(titleText: string): number` = title length times `TAG.CHAR`, clamped to `TAG.MIN_WRAP..TAG.MAX_WRAP`
- Produces (`src/flow.mjs`): `boardMermaid(pd, mode = 'tags')`, `treeMermaid(pd, mode = 'tags')`, `nodeMermaid(pd, id, mode = 'tags')` where `mode` is `'tags'` or `'plain'` (`'plain'` is today's `title<br/>State · id · extras` label); `addTags(svg: string, pd): string | null` (null when the SVG could not be post-processed); `addDiagrams(pd)` tries tags and re-renders in plain mode for any diagram where `addTags` returns null.
